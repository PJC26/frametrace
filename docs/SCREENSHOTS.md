# UI screenshots (regenerate and compare)

`scripts/capture-screens.mjs` builds the workstation, starts it on a free
loopback port against a synthetic dashcam folder, drives the real UI with
Playwright (ko-KR, Asia/Seoul, reduced motion, caret hidden) and writes named PNGs
per viewport size and theme: `<out>/<WxH>-<theme>/<name>.png` (default sizes
1366x768 and 1920x1080, themes light and dark). Every size x theme combination
runs against its own isolated server (throwaway HOME/XDG config, pinned token,
explicit port), so it never touches `~/.config/frametrace` or `~/.frametrace`.

| Path | Purpose |
|---|---|
| `docs/screens/current/` | latest capture of the working tree (regenerated by the script) |
| `docs/screens/before/` | baseline of the UI as of the pre-v1.0.0 commit `6a46590` (flat, 1440x900) |
| `docs/screens/before-ux/` | UX-overhaul BEFORE baseline (commit `e69a66b`), all sizes x themes; compare other tracks against it |
| `docs/screens/diff/` | output of `scripts/visual-diff.mjs` (HTML report) |
| `docs/screens/INDEX.md` | contact page: every current screenshot with a one-line description |
| `scripts/make-demo-case.mjs` | synthetic dashcam source folder generator (ffmpeg, no real footage) |
| `scripts/visual-diff.mjs` | before/after/diff HTML report with pixel-diff % per screen |
| `scripts/check-js.mjs` | CI syntax check for viewer bundle + inline shell scripts |

## Prerequisites

- Rust toolchain (the script runs `cargo build --bin frametrace-app`)
- `ffmpeg` on PATH (or `FFMPEG=/path/to/ffmpeg`)
- Node 18+ and Playwright: `npm i --no-save playwright`. With a Chromium
  already installed, set `CHROMIUM_PATH` (default `/opt/pw-browsers/chromium`
  when present) and skip `npx playwright install`.

## Regenerate

```sh
node scripts/capture-screens.mjs                 # -> docs/screens/current/<WxH>-<theme>/ + INDEX.md
node scripts/capture-screens.mjs --sizes 1366x768            # one viewport (comma list for more)
node scripts/capture-screens.mjs --themes light              # one theme (--theme dark also works)
node scripts/capture-screens.mjs --out /tmp/after-ux         # other output dir
node scripts/capture-screens.mjs --no-build      # reuse the last build
node scripts/capture-screens.mjs --keep          # keep the temp case/source for inspection
```

On a shared Linux box use your own target dir, e.g.
`CARGO_TARGET_DIR=/tmp/ft-target-me RUSTUP_TOOLCHAIN=stable-x86_64-unknown-linux-gnu`
(or `--target-dir`). The script exits non-zero if a step fails (a
`zz-failure.png` shows where) or any image is suspiciously small (blank).

Generate just the demo source folder:

```sh
node scripts/make-demo-case.mjs /tmp/demo-source --clean
```

Screens (names are stable; docs/ui-rebuild-contract.md §9.4): `00-empty`
(two blocks), `01-empty-options`, `01b-empty-filled` (detected-kind chip +
preflight line), `02-running` (progress chip + jobs sheet opened once on the
first start), `02b-running-chip` (sheet closed, chip only), `03-project` (viewer
hosted in the shell; its description records how many grid rows are fully
visible), `03a-project-menu` (project switcher), `03b-jobs-sheet` (recover job
failed on the demo case), `04-viewer-grid`, `05-viewer-detail`,
`05b-viewer-inspector` (details panel scrolled to 포렌식 인스펙터), `05c-shortcuts`,
`05d-clip-dialog` (falls back to the "no range" toast if the dialog cannot open),
`06-viewer-multiselect`, `06b-toast-actionbar` (standalone viewer toast),
`06c-toast-hosted` (three toasts with a sheet open), `07-finalize-sheet`,
`07b-finalize-blocked` (unsaved marks block the package), `08-finalized`
(report links + package path), `09-alt-theme`, `10-popout` (main window while
video + verdict are in the second window; `window.open` is stubbed).

The capture never uses frame APIs (`page.frames()` / `frameLocator`): the
viewer is hosted in the shell document. Until the viewer fragment is hosted,
the legacy viewer frame inside `#hViewerHost` is read through its same-origin
`contentDocument`. `visual-diff.mjs` matches by name, so comparisons against
`before-ux` need a manual name map (00-onboarding → 00-empty, 03-review-embedded
→ 03-project, 07-finalize → 07-finalize-sheet, 08-report → 08-finalized).

## Compare before / after (visual-diff)

```sh
node scripts/capture-screens.mjs --out /tmp/after-ux
node scripts/visual-diff.mjs docs/screens/before-ux /tmp/after-ux          # -> docs/screens/diff/index.html
node scripts/visual-diff.mjs docs/screens/before-ux /tmp/after-ux --out /tmp/diff --fail-over 5
```

The report lists every screen with its changed-pixel percentage and shows
before / after / diff side by side. It uses `pngjs` when resolvable and
otherwise a built-in PNG decoder; no install is required. Temp paths and case
ids in text legitimately differ between runs (a fraction of a percent).

## Compare with ImageMagick (older flat layout)

Capture a baseline from any older commit without touching your working tree:

```sh
git worktree add --detach /tmp/ft-before <commit>
node scripts/capture-screens.mjs --repo /tmp/ft-before --out docs/screens/before
git worktree remove /tmp/ft-before
```

Then capture the current tree and diff by file name (same names in both
directories). For a visual diff, ImageMagick works well:

```sh
for f in docs/screens/current/*.png; do
  b=docs/screens/before/$(basename "$f"); [ -f "$b" ] || continue
  compare -metric AE "$b" "$f" /tmp/diff-$(basename "$f") 2>&1 | sed "s|^|$(basename "$f"): |"
done
```

Known stable differences: temp paths and case ids in the log/report text, and
the media player area (headless Chromium usually cannot decode H.264, so the
player is black and thumbnails read "썸네일 없음"). Screenshots that exist only
in `current/` (for example `07b-finalize-precheck`) are new UI.

## CI

`.github/workflows/ci.yml` (`screenshots` job) runs the same script on Ubuntu
and uploads `docs/screens/current/` as the `ui-screens` artifact.

## Baseline size note

`docs/screens/before-ux/` is committed as reference PNGs. See the commit
message for its size; if it grows past ~25 MB, keep 1366x768 + 1920x1080 light
and only 1366x768 dark.

Current `before-ux/`: 4 combinations x 17 screens, about 19 MB (under budget, so
all sizes and themes are kept). It was captured with Playwright's
chromium-headless-shell 1228 (`CHROMIUM_PATH=...`), which decodes the demo H.264,
so the player and thumbnails are populated. Compare only against captures made with
the same Chromium. Run-to-run noise is under about 0.3% (a transient
"보강 완료" toast in the shell, `01b` preflight text); the case-id/temp-dir text is masked.
Observed in the baseline: at 1366x768 the standalone viewer overflows horizontally
(`05d`, `05b` show the left edge clipped) and the embedded stage-3 grid shows 0 fully
visible rows.
