### 트랙 U 계약 — `/api/status.finalize_journal` (R16 계약에 추가)
- **`writer_gone_command`**, **`writer_gone_command_cmd`** (새, string|null): `in_progress_code`가 `unverified-writer`·`other-account`일 때만 문자열(`frametrace finalize-journal '<case>' --writer-gone`; cmd 형식은 Windows이고 경로에 `%`가 없을 때만). U5: 차단 행에 "작성자가 없다고 확인했다면 정상 복구" 명령으로 이 필드만 표시(직접 만들지 말 것; null이면 숨김). force보다 앞에.
- **`force_dismiss_command(_cmd)`**: 이제 **`live-writer`에서 null**(S8). `unverified-writer`·`other-account`만 문자열. U3: 옆 고정 문구 "저널만 옮김 — 아무것도 되돌리거나 기록하지 않음(서명·패키지 그대로 남음)".
- `live-writer`의 `reason`: "…기다리십시오: 그 최종화가 끝나거나 그 프로세스가 끝나면 다음에 케이스를 열 때 저절로 정리됩니다." — 명령 없이 기다림만.
- `unverified-writer`/`other-account`의 `reason`: "기다리면 저절로 풀립니다(…)"가 먼저, 그 뒤 `--writer-gone`, `--force`(남는 서명·패키지 이름 포함) 순. 문장을 그대로 보이면 됨.
- **`manifest_check`** (새, `"withheld"`|null): `"withheld"`면 manifest가 16 MiB 초과라 상태 확인에서 해시하지 않음 — `state: "completed-unrecorded"`는 로컬 기록의 말일 뿐 "확인 보류"로 표시(완료 확정처럼 보이지 말 것), `blocks_finalize: false`(최종화가 먼저 전체 확인).
- `dismiss_command_cmd`·`force_dismiss_command_cmd`·`writer_gone_command_cmd`는 Windows에서도 경로에 `%`가 있으면 null — PowerShell 형식만 표시.
- `state: "completed"`(레인이 닫음)는 작성자가 살아 있어도 이제 `in-progress`가 되지 않음(S7).
- 새 CLI 문구는 `finalize_incomplete`/로그에 "열린 기록 파일을 지웠습니다 — 이 최종화는 앞으로 자동으로 되돌려지지 않습니다"가 나올 수 있음(표시만).

**기존 동작 변화:** 디스크가 꽉 찬 PC에서 끝난 최종화는 로컬 기록 없이 끝남(재구성 저널은 "로컬 기록 없음"); complete 기록까지 실패한 경우 남은 저널은 `completed-unrecorded`가 아니라 `unpaired`/`no-local-record`로 보이고 이 PC가 완료를 다시 기록하지 않음(dismiss). 찢긴/읽기 전용 레인 케이스는 이제 이전 저널 복구도 하지 않고 거부(케이스 열기·서버 시작 복구는 그대로). 재사용 pid의 다른 계정 프로세스는 시작 시각이 다르면 차단하지 않음.

### 트랙 U 계약 (정확한 이름)
- **`reason_code` 새 값 `"marker-unusable"`** — `/api/records-meta` `logChains.anomaly.head.reason_code`, 보고서 `auditChains.anomaly.head.reason_code`, 번들 `logChains.anomaly.head.reason_code`(이상 징후 레인만; `/api/verify-sources` `head_reason`에는 안 나옴). `status: "unknown"`, `withhold_reason`은 `"이상 징후 머리 확인 불가 — 결과 없음: 완료 표식을 쓸 수 없음 — "`으로 시작. U1 표시: 변조 가능성 문구(예 "이상 징후 기록: 완료 표식을 쓸 수 없음 — 지워졌거나 HMAC이 제거됐을 수 있음"), **"다시 스캔하면 해소"를 붙이지 말 것**, 이전 버전/버전 혼재로 쓰지 말 것. "다시 스캔하면 해소"는 `mixed-version`에만.
- **`head_reason: "scan-mismatch"`**가 이제 재검증 레인에서 결과 실행에 머리가 없는 경우에도 나옴(의미 같음: 현재 결과 없음).
- **`unusable-line` 문장 변경**: "구조적으로 다른 이벤트 … 변조 판정 아님" → "모양상 다른 이벤트이나 내용은 인증 안 됨 — …". 문장을 그대로 보이는 UI는 변경 없음; 이 문구를 키로 쓰는 곳이 있으면 `HEAD_OTHER_EVENT_NOTE` 새 값으로.
- **번들 `logChains`** (U4): `review/data-bundle.js`에 `logChains: {anomaly: {head: {status, reason_code, withhold_reason, detail}}}`만 있음(다른 레인 키 없음 → `logChainItems` 등은 표시 없음 그대로). 뷰어 `anomalyHeadState(logChains)`가 이미 읽으므로 같은 배너가 뜸. 번들 출처이므로 `detail`·`withhold_reason`의 "이 PC"는 생성 PC(§17.3 규칙대로 "생성 PC"로 바꿔 보일 것 — 현재 `anomalyHeadState` tip은 바꾸지 않음). 계약 문서 §17.3의 "`logChains` 없음(구 서버·번들)" 문구 갱신 필요.
- **타임라인 `time_self_consistent: boolean`** (새, 모든 이벤트): true면 "시각 자기 일관성만(인증 아님)" 같은 약한 표시(배지 `시각 감사 안 됨`과 구분). 필드 없음(옛 출력) = false로.
