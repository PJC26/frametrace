### 트랙 U 계약 (정확한 이름)
- **`reason_code` 새 값 `"marker-unusable"`** — `/api/records-meta` `logChains.anomaly.head.reason_code`, 보고서 `auditChains.anomaly.head.reason_code`, 번들 `logChains.anomaly.head.reason_code`(이상 징후 레인만; `/api/verify-sources` `head_reason`에는 안 나옴). `status: "unknown"`, `withhold_reason`은 `"이상 징후 머리 확인 불가 — 결과 없음: 완료 표식을 쓸 수 없음 — "`으로 시작. U1 표시: 변조 가능성 문구(예 "이상 징후 기록: 완료 표식을 쓸 수 없음 — 지워졌거나 HMAC이 제거됐을 수 있음"), **"다시 스캔하면 해소"를 붙이지 말 것**, 이전 버전/버전 혼재로 쓰지 말 것. "다시 스캔하면 해소"는 `mixed-version`에만.
- **`head_reason: "scan-mismatch"`**가 이제 재검증 레인에서 결과 실행에 머리가 없는 경우에도 나옴(의미 같음: 현재 결과 없음).
- **`unusable-line` 문장 변경**: "구조적으로 다른 이벤트 … 변조 판정 아님" → "모양상 다른 이벤트이나 내용은 인증 안 됨 — …". 문장을 그대로 보이는 UI는 변경 없음; 이 문구를 키로 쓰는 곳이 있으면 `HEAD_OTHER_EVENT_NOTE` 새 값으로.
- **번들 `logChains`** (U4): `review/data-bundle.js`에 `logChains: {anomaly: {head: {status, reason_code, withhold_reason, detail}}}`만 있음(다른 레인 키 없음 → `logChainItems` 등은 표시 없음 그대로). 뷰어 `anomalyHeadState(logChains)`가 이미 읽으므로 같은 배너가 뜸. 번들 출처이므로 `detail`·`withhold_reason`의 "이 PC"는 생성 PC(§17.3 규칙대로 "생성 PC"로 바꿔 보일 것 — 현재 `anomalyHeadState` tip은 바꾸지 않음). 계약 문서 §17.3의 "`logChains` 없음(구 서버·번들)" 문구 갱신 필요.
- **타임라인 `time_self_consistent: boolean`** (새, 모든 이벤트): true면 "시각 자기 일관성만(인증 아님)" 같은 약한 표시(배지 `시각 감사 안 됨`과 구분). 필드 없음(옛 출력) = false로.
