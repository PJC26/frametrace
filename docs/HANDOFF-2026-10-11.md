## 2. 오늘 한 일 (요약)

1. **v100 라운드 반영**: Cowork 세션 결과(패치)를 `git am`으로 적용·push. CI 고장 3건 수정(Windows 계약 해시 CRLF → `.gitattributes`, cargo-audit 설치, deepfake python 대체 경로 테스트).
2. **v1.1 라운드** (병렬 트랙 6개): 2단계 파이프라인(스캔 중 검수), 가상 그리드, IN/OUT 서버 저장(스키마 v5), 기본 랜덤 토큰·하위 프로세스 트리 종료·원본 재검증·최종화 서명, carve/scan 모듈 분리, 프레임 이동·셔틀 키.
3. **적대적 리뷰 → 수정** 반복: 해시 삭제(가벼운 재스캔), 가짜 "이어서", 새 브라우저 구간 삭제, 서명이 구간·태그 미포함 등 차단 문제 수정.
4. **백로그 완료 라운드**: 61건 중 남은 34건 처리 또는 비목표로 문서화(`docs/PLAN-v100.md` §7). 증거 해시 검증·출처, 마크 변경 이력(스키마 v6), `verify-package` CLI, 백그라운드 작업(복구·카빙·클립), HTTP 계층 강화 등.
5. **UI/UX/접근성 개편** → 소유자가 마음에 들어 하지 않아 **전면 재구축**:
   - omo(Fable)로 계획 → 계약 문서 → 5개 트랙 병렬 → 통합.
   - 결과: 단계 1~4와 iframe 제거, **한 화면 통합**(상단 띠 · 왼쪽 필터/달력 · 가운데 그리드 · 오른쪽 영상/상세 · 하단 판정 바), 분석 진행은 상단 칩 + 작업 패널, 결과물은 체크리스트 + 버튼 1개 패널, 빈 화면은 블록 2개(증거 넣기 · 이전 프로젝트), 디자인 "종이 서류 + 영상 스테이지"(잉크 블루, 3px, SVG 아이콘), 중요 마크 = 호박색 깃발.
6. **재구축 적대적 리뷰 → 수정**: 서버 순간 끊김 시 빈 화면 전환, 결과물 패널 깜빡임, 검토자 이름 없는 마크(상단 "검토자" 버튼 + 귀속 버튼), 보조 창 상태 등.
7. **실서버로만 드러난 버그 수정**: 서버는 마크를 `record_id`로 주는데 뷰어는 `id`만 읽어 **새 브라우저·다른 PC에서 저장된 마크·메모·구간이 안 보이던 문제**(DB·보고서는 정상이었음). `scripts/verify-marks-roundtrip.mjs`(실서버 왕복)를 CI에 추가.

## 3. Windows에서 할 일 (가장 중요 — 아직 한 번도 실제 Windows 앱을 띄우지 않았다)

준비는 [WINDOWS_USAGE.md](WINDOWS_USAGE.md)의 설치 절차(Rust MSVC, Node 20+, FFmpeg, libewf, Sleuth Kit)를 따른다.

```powershell
git pull
cargo build --release --locked
.\target\release\frametrace-app.exe        # 브라우저/WebView2로 워크스테이션이 열린다
```

체크리스트 (결과를 이 문서 아래 "검증 기록"에 남길 것):

- [ ] **앱 실행**: `frametrace-app.exe`가 뜨고 빈 화면(증거 넣기 · 이전 프로젝트)이 보인다. 토큰 오류(빈 화면/401) 없음.
- [ ] **WebView2 셸**(`src/shell.rs`): 셸 창이 열리고 토큰을 서버에서 직접 받는다(인스턴스 파일 없이도).
- [ ] **실제 블랙박스 폴더/드라이브**(`E:\` 등): 경로를 넣으면 "폴더" 칩, 사전 점검 한 줄, 분석 → 검토까지 진행. 분석 중에도 그리드가 채워진다.
- [ ] **진짜 E01**: "E01 이미지" 칩, libewf로 분석 완료. (가짜 E01로는 판별·흐름 진입까지만 확인했다.)
- [ ] **복구(삭제 영상 후보)**: Sleuth Kit + 실제 디스크 이미지로 끝까지. (macOS에서는 거부 경로만 확인했다.)
- [ ] **마크 보존**: 마크·메모·태그·IN/OUT 지정 → 앱 종료 → 재실행 → 그대로. 다른 브라우저/포트에서도 보이는지.
- [ ] **취소·종료 시 하위 프로세스 정리**: 분석/카빙 중 취소, 콘솔 Ctrl+C, 창 닫기 → 작업 관리자에 `ffmpeg.exe`/`frametrace.exe` 잔존 없음 (Job object + `SetConsoleCtrlHandler`, `src/serve/proc.rs`). **CI는 컴파일·테스트만 확인했다.**
- [ ] **보조 모니터**: "새 창" → 영상+판정만 분리, 본 창 그리드 유지, 저장은 한 창.
- [ ] **키보드**: 한글 IME 상태, AltGr, CapsLock에서 j/k/1/2/3/0, Alt+P/J/R, Shift+J/K/L.
- [ ] **화면**: Windows 기본 글꼴(맑은 고딕)·스크롤바·배율 125/150%에서 버튼 잘림/가림 없음, 밝은/다크 테마(◐).
- [ ] **스크린리더**(가능하면 NVDA): 상단 띠 → 그리드 → 판정 바 읽기 순서, 버튼 이름.
- [ ] **게이트를 Windows에서 실행**: CLAUDE.md의 게이트 블록(하네스는 Git Bash에서 `bash scripts/ci-harnesses.sh`). 실패하면 원인과 함께 기록.
- [ ] **성능(실데이터)**: 수천~수만 개 영상 폴더에서 첫 화면까지 시간, 그리드 스크롤, 메모리. (지금은 합성 데이터 벤치만 있음: 1만 건 그리드 ~3ms/render — `scripts/bench-viewer.mjs`의 `ROWS = 10_000`; 과거 문서의 "5만 건"은 오기.)
- [ ] 첫 실기: 포터블 zip을 풀고 `frametrace.exe tools install ffmpeg` → doctor의 ffmpeg 줄이 "libx264 없음 — H.264는 h264_mf 사용"인지, 프록시·MP4 내보내기가 h264_mf로 실제 인코딩되는지(CI 스모크는 설치·probe까지만 본다).

## 8. 테스트 부채·직렬화 메모 (3단계 Track D)

**T14 — 프로세스 전역 env를 바꾸는 단위 테스트** (`cargo test`는 스레드 병렬): 지금은 각자 고유한 변수명을 쓰거나 한 테스트가 set→호출→remove를 짧게 끝내 충돌 가능성이 낮지만, 같은 변수를 읽는 다른 테스트와 겹치면 비결정적이 될 수 있다. 해당 코드는 다른 트랙 소유(`src/**`)라 이번에는 고치지 않았다. 후속 작업:

- `src/serve/tests_hardening.rs` — `FRAMETRACE_INSTANCE_FILE` set/remove 2회(R4 F9: 이 파일 안에서는 `ENV_LOCK`으로 직렬화함; 같은 변수를 읽는 다른 파일의 테스트와는 여전히 미직렬화)
- `src/deepfake.rs` — `FRAMETRACE_DEEPFAKE_LENS` set/remove
- `src/serve/tests.rs` — `FRAMETRACE_TEST_SPEW` set/remove (고유 이름이라 위험 낮음)
- `src/audit_key.rs` — `FRAMETRACE_TEST_KEY_SOURCE` (고유 이름이라 위험 낮음)
- 권장: 공용 `static ENV_LOCK: Mutex<()>` + RAII 가드(set 시 이전 값 저장, Drop에서 복원), 또는 env 대신 함수 인자로 주입.
