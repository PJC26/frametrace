# 11라운드 수정 계획 — 10라운드 적대적 리뷰 (2026-10-16, 기준 6e52014)

## 0. 원칙 확장
R10의 P7(최신성)은 "같은 기록의 더 새 줄"에만 걸린다. 실행 단위 요약(완료 표식)과 체인 파손은 키가 없어 비켜 갔고, 미인증 줄이 **빠짐으로써** 결과가 좋아지는 소비자가 남았다.

> **P9. 빠진 줄은 좋은 소식이 아니다.** 실행(run) 안에 사용 불가 줄이 하나라도 있거나 레인에 체인 파손이 있으면, 그 레인에서 나온 "모두 일치·전체 완료·현재값" 주장은 금지한다(배너·API 요약·보고서 지표 동일). 실행 단위 레코드(`hash-verify-run` 등)는 `run_id`로 P7에 묶는다.
> **P10. 비밀은 읽는 즉시 환경에서 뺀다.** `--key-source env:VAR`를 포함해 키를 읽는 모든 경로가 같은 adopt 함수를 거친다.
> **P11. 경로 판정은 정규화된 경로로.** `_INCOMPLETE` 판정·옆 표식·레인 식별은 canonicalize(긴 이름, 끝 점·공백 제거, `\\?\` 제거) 뒤에만 한다. 복사본 꼬리(` - 복사본`, ` (n)`)를 허용한다.

공통 규칙은 `PLAN_R4_2026-10-14.md` §0.

### 트랙 U 계약
- **`POST /api/finalize` 실패**(`ok:false`): `error`(한국어; 원인 + 남은 것 설명을 공백으로 이어 붙임), `report_stale: bool`, `finalize_incomplete: bool`. **R10의 `incomplete_package_dir`·`incomplete_package_url`은 더 이상 오지 않음**(최종화는 미완료 패키지를 만들지 않음). 승격 실패 문구: "검토자 기록 확정 실패: … — 최종화는 끝나지 않았고 패키지는 만들지 않았습니다 …".
- **`POST /api/finalize` 성공**: 기존 필드(`package_url`, `package_dir`, `manifest_sha256`, `examiner`, `incomplete_packages`) + `report_stale: false`.
- **`/api/status` 새 필드**: `report_stale: bool`(보고서가 끝나지 않은 최종화의 서명으로 만들어진 채 남음 — "보고서 다시 만들기 필요" 표시), `finalize_incomplete: bool`, `finalize_incomplete_detail: string|null`(무엇이 남았는지; 표시용 한국어). 둘 다 최종화 성공 시 false/null, 다른 케이스로 바뀌면 초기화. 메모리 상태 — 서버 재시작 후에는 사라짐.

- **`_INCOMPLETE` 이름 규칙(서버와 같게)**: 이름 끝에서 점·공백, ` - 복사본`, ` - Copy`(대소문자 무시), ` (숫자)`를 반복해 뗀 뒤 `_INCOMPLETE(_숫자)?`로 끝남(대소문자 무시). JS 등가: `const core = name.replace(/(?:[ .]+| - 복사본| - copy| \(\d+\))+$/i, ''); /_INCOMPLETE(_\d+)?$/i.test(core)` (반복 제거가 정확히 같으려면 루프로). U3 정규식 `/_INCOMPLETE(_\d+)?( - 복사본| \(\d+\))?$/i`는 ` - Copy`·꼬리 2개 이상·끝 점을 놓침. 가능하면 서버 판정(`incomplete_packages`, `package_incomplete`)을 그대로 쓰고 정규식은 표시 보조로만.
- **`verify-package --strict`**: 종료 코드 0 = 검증 통과(NOT VERIFIED 줄 제외), 1 = FAIL 있음, **3 = 파일은 맞지만 FINALIZE INCOMPLETE**. `--strict` 없으면 미완료도 0.
