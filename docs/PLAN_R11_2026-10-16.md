# 11라운드 수정 계획 — 10라운드 적대적 리뷰 (2026-10-16, 기준 6e52014)

## 0. 원칙 확장
R10의 P7(최신성)은 "같은 기록의 더 새 줄"에만 걸린다. 실행 단위 요약(완료 표식)과 체인 파손은 키가 없어 비켜 갔고, 미인증 줄이 **빠짐으로써** 결과가 좋아지는 소비자가 남았다.

> **P9. 빠진 줄은 좋은 소식이 아니다.** 실행(run) 안에 사용 불가 줄이 하나라도 있거나 레인에 체인 파손이 있으면, 그 레인에서 나온 "모두 일치·전체 완료·현재값" 주장은 금지한다(배너·API 요약·보고서 지표 동일). 실행 단위 레코드(`hash-verify-run` 등)는 `run_id`로 P7에 묶는다.
> **P10. 비밀은 읽는 즉시 환경에서 뺀다.** `--key-source env:VAR`를 포함해 키를 읽는 모든 경로가 같은 adopt 함수를 거친다.
> **P11. 경로 판정은 정규화된 경로로.** `_INCOMPLETE` 판정·옆 표식·레인 식별은 canonicalize(긴 이름, 끝 점·공백 제거, `\\?\` 제거) 뒤에만 한다. 복사본 꼬리(` - 복사본`, ` (n)`)를 허용한다.

공통 규칙은 `PLAN_R4_2026-10-14.md` §0.

### 트랙 U 계약 (정확한 이름)
- **`POST /api/verify-sources` 성공 응답** (`ok:true`): 기존 `run_unix`·`matched`·`mismatched`·`not_comparable`·`log`·`custody_url` + 
  - `run_id`: string | null (결과 실행 id; `is_result:false`면 null)
  - `unauthenticated`: number — 결과 실행과 그 뒤 실행(결과 없으면 전체)의 이 PC에서 쓸 수 없는 `hash-verify`/`hash-verify-run` 항목 수
  - `verified`: bool — 결과 실행 전체를 믿어도 됨(체인 정상, 레인 NOT VERIFIED 아님, 사용 불가 항목 0, 표식 `records` = 사용 가능 기록 수)
  - `is_result`: bool — false = **현재 결과 없음**(더 새 실행 인증 불가 또는 체인 파손; 수치는 0, 이전 실행으로 대체 안 함)
  - `not_verified_reason`: string | null (한국어, `; `로 연결)
  - `lane_status`: `"keyed"|"structural"|"not-verified"|"failed"|"absent"` (`structural` = 자기 일관성만, P1)
  - **초록("모두 일치")은 `verified && is_result && mismatched==0 && not_comparable==0 && matched>0`일 때만.** `is_result:false` → "현재 결과 없음(결과 아님)" + 사유, `verified:false` → "확인 불가(NOT VERIFIED)" + `unauthenticated`·사유. 서버 작업 로그 줄도 `… · 인증 안 됨 N — 확인 불가(NOT VERIFIED): …` / `— 현재 결과 없음(결과 아님): …`.
